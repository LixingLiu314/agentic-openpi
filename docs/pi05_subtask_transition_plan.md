# π0.5 subtask 完成与及时切换：分析及开发方案

初始日期：2026-09-07；状态更新：2026-09-08。R1a 已完成1000步，但四次验证均无合格候选，step1000 的代理与动作门槛失败；物理ready审核和R2仍未完成。实机失败复盘及修正顺序见第15节与 docs/pi05_subtask_transition_failure_review_20260908.md。以下各节保留其撰写时的方案/执行历史，不把早期“尚未训练”快照当作当前状态。

用户报告：完成一个 subtask 后，机械臂停滞很久才进入下一个 subtask。用户进一步确认，停滞期间显示的 subtask 文本也一直停留在旧阶段。

结论：问题合理，当前模型的已有评估也支持边界判断偏弱、偏晚的判断。可以通过针对性监督和时间信息改善，但尚未量化用户这次现象的具体等待秒数，也不能承诺仅改文本预测就消除全部动作停顿。优化目标是“后继策略具备接手条件后及时、稳定地交接，同时避免越过必要前置条件”，并分别测量语义切换与动作响应。

用户后续提出：夹爪开合相关阶段应避免提前结束，其他阶段可考虑为效率稍早几帧交接。方案据此细化为“按具体 old→new 边界及后继策略的前置条件，学习可接受交接窗口”。允许早于示教标签，不允许早于后继动作可执行的条件；详见第 12 节。本节对所有边界一律禁止提前的旧理解具有优先级。

**2. 为什么会出现这个问题**

目前的计算路径是：

```text
当前三视角图像 + 当前 native14 状态 + 全局任务
    → 冻结的 VLM B
    → subtask Transformer S，从 BOS 重新生成文本
    → 根据该文本重建 action prefix
    → action expert A，预测 50 步
    → 客户端执行前 15 步，再重新观测
```

- `src/openpi/models_pytorch/pi05_subtask_pytorch.py::prepare_context` 只构造当前时刻上下文。`subtask_policy.py::infer` 没有跨请求历史，也没有显式完成头。
- `subtask_decoder.py::compute_loss` 是当前帧文本的 token CE；没有边界完成、下一阶段选择或切换时刻的监督。文本 EOS 只表示句子结束。
- `subtask_batch.py::BalancedSubtaskSampler` 在 M1 做 task/subtask 均衡；`train_subtask_hierarchy.py` 的 M2/M3 则使用普通帧采样。两者都没有边界专项采样；不能把当前实现描述成已经做了边界均衡。
- M3 按 generated-condition action flow 指标选择 checkpoint，没有把切换延迟、提前切换和抖动作为主选择指标。
- 当前双分支梯度隔离意味着 action loss 不能纠正 S 的阶段判断。应给 S 增加它缺少的监督，保留用户要求的隔离；统一放大所有 subtask CE 不等同于强化边界。

可能的闭环机制是：完成附近的画面与动作进行中很相似，S 仍预测旧阶段；旧阶段动作让机器人停留在相似状态，下一次观测仍触发相同判断。短历史可以帮助区分“刚接近”与“已经抓住并发生运动”等状态。这是有依据的机制假设，尚需边界定点干预来建立因果证据。

动作分支未必会完全听从 subtask。现有 128 帧/2 draws 的全局验证中，generated 与 oracle 条件的 normalized native14 flow MSE 分别为 0.03237188、0.03229351，差异很小；shuffle 为 0.03437821。全局平均结果没有证明“换成正确文本就能解除停滞”，下一步必须在边界帧单独比较，而不能以文本改善代替动作改善。

**3. 开发顺序与停止条件**

采用同一个 seed42，保留原 M3 为 R0。按 R1 → 必要时 R2 推进；R1 已达到可部署门槛就先交付真机测试，不为等完整实验矩阵而延迟。用户已取消多随机种子实验。

| 阶段 | 工作 | 可交付物与进入下一步条件 |
| --- | --- | --- |
| D0：诊断和边界审计 | 事件级指标、人工完成区间、边界动作条件干预 | 明确晚在哪里；标签质量足以训练后进入 R1 |
| R1：最小改动 | 边界强化 S 微调，B/A 冻结，架构不变 | 可直接兼容现有动作分支的候选；通过门槛就交付 |
| R2：按需升级 | 因果短历史 + 条件完成头 + 后继文本生成 | R1 仍存在持续滞留/状态混淆时再做 |
| A1：按需适配动作 | S 冻结，只微调 A 适应新语义切换 | 仅在文字改善但动作交接仍弱时执行 |
| C1：单独处理控制延迟 | 时间对齐的异步 action chunking | 仅在确认剩余停顿主要来自阻塞推理后执行 |

本轮只交付方案。新对话需从 D0 开始，不能因为旧研究计划有排队项而自动恢复 seeds43/44、旧 finalizer 或无关基准。

**4. D0：首先明确“结束”和“切换”的标注**

从 train 的 1,106 个边界生成索引，保存 episode、原始帧号、old/new 标签、左右边界距离。固定原 split、归一化与标签原始文件，边界审计使用独立的版本化 sidecar。

未来边界位置、完成标注和目标阶段只用于训练监督/采样与离线评分，不得作为推理输入；相机历史、状态差分和缓存都只允许使用当前及过去的真实观测。

先选约 20 条训练轨迹，覆盖两个任务及全部 7 类阶段位置，对每个边界观看至少前后 1 秒的三视角片段。验证集也需形成独立、固定的事件评估标签，绝不混入训练。人工给出 `完成尚未成立的最后时刻` 和 `完成已经成立的最早时刻`，不强迫视觉模糊事件具有精确到一帧的真值。

例子：

- reach → grasp：已经进入可开始闭合夹爪的位置。它不要求物体已经被夹住。
- grasp → move：有支持抓取成立的观测，具备开始搬运的条件；夹爪闭合命令本身不等于抓取成功。
- move → release：物体到达允许释放的目标区域；提前进入该标签可能造成掉落。
- release → 下一阶段：释放条件成立，而不只是发出了张开夹爪指令。

若下一步动作才会让完成证据变得明显，要把该事件标成不确定，结合可观测的接触/夹爪/位置条件复核，避免训练出“必须先执行下一阶段才能宣布上一阶段完成”的循环。

记录标签切换是否落后于真实动作启动、是否含示教人的停顿。标签跳变只提供弱边界，不能未经检查就等同于物理完成。最后一个阶段的 episode 截止也不能直接作为任务成功标签。

为一段滞留事件拆出以下时间：

```text
t_complete：人工确认完成条件成立的时间/区间
t_ready：后继策略已经可以接手的最早时间/区间，可能早于示教的 t_complete 或标签切换
t_input：模型看到完成状态的观测时间
t_text_first：模型首次返回正确新 subtask 的响应时间
t_text_confirm：后续实际观测支持该次切换稳定成立的响应时间；离线确认不反向推迟首次响应
t_command：第一条受新 subtask 条件化的实际动作命令
t_motion：机械臂实际开始下一阶段运动
```

分别报告可见性/采样延迟、文本选择延迟、命令交接延迟和物理响应延迟。新 run.json 已有输入/响应及动作步时间；t_motion 需由实际状态/视频标注，不能把发送命令当成已经运动。最近查看的若干新运行在 CAN 检查或复位阶段失败且 query=0，应排除出 subtask 模型评估。

对已审计边界，固定观测与 flow noise，比较 generated、old、正确 new、drop 四种内部动作条件下的首 15 步预测。这个 oracle 干预仅用于离线诊断，禁止作为部署观测输入。先检查 new 条件是否使动作更接近示教的正确交接；闭环因果效果仍需实机验证。

**5. R1：边界强化训练，优先形成可部署候选**

从 R0 权重开始，新建实验目录和优化器，不对旧 M3 进行“精确续训”，不改写旧 checkpoint/optimizer/counter/资产。

- 冻结 B 与 A，只更新 S，保留当前文本生成及 native14 action 接口。
- 每个 batch 初始使用 50% 稳定阶段帧、50% 边界附近帧。边界组先均衡 task/transition/episode，再选帧，避免少数长片段主导；边界前后都要有样本。
- 初始边界窗口为前后约 0.5 秒（15 帧），短阶段窗口须裁剪/去重；根据 D0 标签不确定区间做 mask 或较低权重。
- 先试 500–1,000 个 S 更新，初始 LR 可用旧 S LR 的 0.1 倍（例如 1e-5）；这些是起始配置，不是已经验证的最优参数。
- 现有 CE 已先按每条文本的有效 token 数归一化，再对有标签样本求平均；R1 应暴露逐样本 loss/有效 mask/权重接口，保留默认结果，不必另改成 token 总平均。可辨识的允许交接区间可附加“new 文本优于 old 文本”的对比项，未满足前置条件时使用相反方向；监督优先遵循第 12 节 sidecar，不能只按原标签前后决定方向。sequence log-likelihood 同样按长度归一化。

建议先运行纯边界混合 CE；确有需要才加入对比项，避免同时叠加大采样权重和大 loss 权重。

```text
L_S = L_text_CE_on_mixed_samples + λ_pair L_old_new_ranking
λ_pair 初始为 0；增加时可从 0.1 开始。
B、A 的参数不更新，原 action loss 不参与这个阶段。
```

禁止把所有标签统一向前平移，或让边界之前已经完成的概率被强行设为 1。边界后正确标签与原动作监督必须经过 D0 对齐。

选模不再只看全局 F1/flow MSE。使用第 8 节的事件级验证门槛，同时复测已有动作分支在新 S 条件下的行为。冻结 A 只表示其权重未变，不意味着输入文本分布改变后行为必然不变。

**6. R2：因果短历史和明确的完成判断**

若 R1 仍滞留，增加一个属于 S 分支的时间模块 T 和阶段条件完成头 D，保留原 autoregressive subtask decoder；用它学习何时保持、何时生成后继文本。

```text
当前及过去观测 → 冻结 B → detach 的观测特征
                                ↓
                   T：短历史 + 相对时间 + 状态变化
                                ↓
          上一次模型自己的活动 subtask → D：是否可结束当前阶段
                                ↓
                   S：保持当前阶段 / 生成后继文本
                                ↓ 硬文本，断开梯度
                   冻结 B 重建 prefix → A → 动作
```

“上一次 subtask”是模型内部的历史输出，不是部署时人工/数据集注入的条件。首个时刻从当前观测初始化，不硬编码总是第一阶段；重连、复位、新 episode 和任务变化时清空历史。

时间输入初版 K=4，使用最近 4 次实际推理观测，按实测约 0.7 秒间隔通常覆盖约 2 秒；显式携带相对时间与有效 mask，过旧的历史清空。训练使用相近间隔并做时间间隔扰动，不能用 4 个相邻 30fps 帧去替代部署的 4 次低频观测。缺失历史使用 mask，避免跨 episode 拼接。

缓存过去观测的冻结 B 特征，每次请求只为当前观测新增一次 vision + observation prefix 计算，避免把历史特征提取成本直接乘 4。生成文本后的 action prefix 仍须重新计算；现有路径是一次 vision、两次 language prefix，不能把缓存收益写成整个 B 只运行一次。旧帧可按每视角 4×4 网格压缩为 16 个 token，保留视角/位置/相对时间和 native14 状态；当前帧保留原完整 memory。若压缩损害抓取判别，应调整腕部视角保留量并实测。不要把生成过 subtask 的 action prefix 当作纯观测历史。

代码中有一个必须处理的梯度细节：现有 `SubtaskDecoder.forward` 在 `memory_projection` 前执行 `memory.detach()`。新增 T 若放在这个 detach 之前，会被意外切断梯度。正确做法是在原始 B 特征处 detach，将 T 与 decoder、D 一起放在 S 的可训练侧，并检查它们确实收到 S 损失梯度。另一个独立限制是现有 prepare_context 和 generate_subtask 都带 @torch.no_grad()：训练 T/D 的 forward 不能包在这些方法内，也不能依赖 greedy generation 反传。训练从冻结特征进入显式可微的 T/D/teacher-forced decoder 路径；部署生成仍可使用 no_grad。

完成监督定义为 `D(H_t, active_subtask)`，回答“这个活动阶段的结束条件此刻是否成立”。不要只训练 `label[t] != label[t-1]` 的单帧脉冲，否则模型错过这一帧后仍可能一直不切换。

- 结束前可确认的帧为负例，重点包含临近完成但仍未完成的困难负例。
- 完成后的一小段确认区间为正例，训练时仍把 old 阶段作为 active 条件，模拟滞留。标签模糊区间 mask。
- old 阶段已不合理、跨越多个阶段或视觉状态与进度矛盾时，不自动当作普通完成正例；进入重新识别/异常样本类别。成功示教不足以训练失败恢复，必要时补少量带人工标注的真实滞留、未抓住、重试片段。
- 用模型在训练轨迹上的因果 rollout 产生自身历史，逐渐替代训练时的正确历史；再补相邻阶段延迟、提前与错误历史扰动。最终验证必须从空历史自由运行，不能始终喂正确的上一阶段。

建议损失为：

```text
L_S = L_text + λ_done L_completion + 可选 λ_pair L_old_new_ranking
L_A = 原 flow-matching loss（若进入 A1 才更新 A）

∇_(S,T,D) L_A = 0
∇_A L_S = 0
∇_B (L_S + L_A) = 0
```

完成头初始可用经过采样校正/验证校准的 BCE。正例过采样会改变概率先验，因此阈值必须在自然分布验证集上校准。不能把现有 `subtask_score`（平均 token log probability）直接当作完成概率。

完成判定与后继文本生成必须一起训练：D 判断完成后，S 应根据当前视觉和自己的 active 阶段生成合理的后继文本。不能只增加一个 gate，却仍依赖一个一直输出 old 的候选生成器。

部署时高置信完成可单次触发；中间置信度可等下一次观测确认，但需显式记录因此增加的等待。不要默认连续 3 次确认——以当前节拍，这本身就会额外增加约 1.5 秒。切换前仍检查后继候选与可观测状态的一致性；长期未完成可以报告停滞，不能用固定超时当成“已完成”。

固定 8 阶段流程可以作为弱后继先验，不能替代视觉完成证据或强制单向推进。重试/重新定位需要恢复路径；相关状态缺训练支持时先保留人工恢复方式。最终任务成功/自动停止不在第一版扩展范围，不能从文本 EOS 或最后一帧推断成功。

现有 WebsocketPolicyServer 共享一个 policy，只处理普通 infer，并不会调用 BasePolicy.reset。因此新增有状态模型时，必须增加明确的 run/session reset 协议，至少按连接隔离状态并在 run_id 改变时 reset，避免不同轮次/客户端互相污染。该改动属于 R2 必做项，R1 无状态模型无需引入。

**7. A1 与控制时序的边界**

如果 S 的事件指标改善而动作仍滞留，冻结 S/T/D/B，只微调 A 使用新 S 自由生成的条件。边界动作样本可重点覆盖首 15 个实际执行步，仍保留常规样本回放。不能给一个真实未完成的抓取状态配上搬运标签，再要求它立即搬运；先审计标签与动作窗口对齐。

目前一个 action chunk 输出 50 步、只执行 15 步，下一次请求前才重新采集，必然有采样反应间隔和约 0.2 秒的历史实测推理等待。它们不能解释全部长期语义滞留，但会限制最后能达到的闭环切换延迟。

R1/R2 验证初期保持 chunk 配置不变以便比较。单纯把 15 步改成 5 步会提高请求频率，也提高同步等待占比，不保证更顺畅。若进入 C1，应采用带时间对齐和跨 chunk 一致性约束的异步执行；不能简单开一个后台请求并拼接旧、新动作。语义切换时也要标明实际使用的 subtask 和 action chunk，不跨不同阶段盲目做长时间平均。

**12. 用户补充：按交接条件允许有限提前，而非要求所有边界严格对齐标签**

用户的效率诉求合理：阶段标签的结束往往包含位置微调、示教人的停顿或人为分段选择，后继策略可能在这些动作完全结束之前就能正常接手。不应把早于标注 3–5 帧一概当成失败。

严格程度应根据“old→new 的交接条件”确定，不能仅根据 old 的名字是否包含夹爪开合确定。以下为需要 D0 核验的初始判断，不是已经验证的控制规则：

| 交接边界 | 初始处理 | 核验重点 |
| --- | --- | --- |
| reach handle/object → grasp | 仅在可接手区域允许很短的提前窗口 | grasp 策略是否还会完成最后的接近/对准，还是一进入就闭合夹爪；后者需要更严格的位置条件 |
| grasp handle/object → move | 严格前置条件 | 抓取已经可靠成立。发出闭合命令、到达某个开度，均不能单独证明抓住了物体；也不要求有物体时机械地闭合到零开度 |
| move away lid → reach object | 可优先研究允许提前 | 盒盖已让开必要空间、抓持仍可靠、下一动作路径无干涉；无需一律等到示教的最终放盖/移盖位置 |
| move object over box → release | 严格前置条件 | 物体已进入允许释放的区域/高度；当前 subtask 是移动，也可能因提前结束而让下一阶段过早松爪 |
| release → subsequent motion | 严格前置条件 | 物体已可靠脱离并获得所需支撑，后续运动不会继续拖动物体；不额外要求与任务无关的完全静止 |
| placement/alignment → subsequent contact or stop | 根据几何与接触要求处理 | 不能因阶段不含夹爪开合就忽略位置、支撑或接触条件；最终成功判定仍需单独定义 |

“提前”要区分三个时间基准：早于人工标签、早于当前技能示教的末端停稳、早于后继动作真正可执行的条件。前两者可能允许，第三者不能仅用节省时间作为理由。子任务文字变更也不代表夹爪立刻动作，必须检查新条件下实际 action chunk 的首段行为。

对每个边界建立 `[t_ready, t_latest]`：t_ready 为后继策略可可靠接手的最早时刻，t_latest 为仍可接受的等待上限。它们与原标签 `t_label` 分开保存。t_ready 可以早于 t_label，但应由画面、状态以及后继策略的动作验证支持；视觉不确定区间单独记录，不直接当作允许提前区间。

可以使用以下事件代价描述评估目标：

```text
C_k(t_switch) = α_k · max(0, t_ready − t_switch)
              + β_k · max(0, t_switch − t_latest)
```

α/β 依边界类型而异。抓取、释放、接触等关键交接重罚越过 t_ready 的提前；经核验兼容的运动交接允许相对标签提前，同时重点减少超过 t_latest 的滞留。窗口内优先比较实际完成时间与成功率，不能靠扩大窗口隐藏迟滞。这是事件级目标，训练时使用对应的标签/权重近似，不直接把不可微的切换时刻当作 CE。

R1 对应调整：

- 先对允许交接的候选片段做内部 old/new 条件动作对比，从 `t_label−3帧` 附近开始审计，再视证据扩展至 5 帧；这些只是候选窗口，不是直接批量前移标签的指令。
- 一旦核验某段时间内后继动作兼容，就在独立 sidecar 中标出“后继已可接手”，对这些帧加强 next-subtask 监督；不确定时可用 old/new 的软目标或低权重。只把 old/new 都设为正确，可能不足以消除旧阶段滞留，还要用效率指标选择候选。
- 对尚未满足抓取/释放/接触条件的帧，保留严格 old 目标与困难负例，不按统一帧数前移。
- 若新标签条件下的 A 会过早闭合、释放或改变轨迹，则该窗口对当前 A 不成立；缩小/取消窗口，或进入 A1 做明确的适配。不能假定下一阶段天然会补完上一阶段。
- 检查 next 条件下旧观测与未来动作的匹配，避免只移动 S 标签却给 A 制造矛盾监督。A 冻结时也必须验证条件改变后的行为。

R2 对应调整：把 D 的操作含义明确为“允许结束当前阶段并交给这个后继策略”，而非必须等到示教当前技能的最后一帧。若存在多个后继，D 还需区分候选后继，因为同一状态可能允许继续接近，却不允许立即释放。严格前置条件的监督保留，subtask/action 梯度隔离不变。

实际节拍必须计入验收：30fps 的 3–5 帧约为 100–167ms；历史模型请求间隔约 764ms。“提前一次模型决策”可能早约 0.7 秒，不能等同于提前几帧。初版用真实时间戳验证早了多少、动作何时生效，不能只降低阈值就宣称实现了精细提前。

后续评价应同时报告：相对原标签的有符号误差、允许窗口内交接率、越过前置条件的提前率、窗口后滞留、抓取/释放结果、整任务成功与完成耗时。效率收益以保持任务可靠性为前提。此补充只更新开发方案，本轮未修改运行中的模型/控制器。

**13.2 两种输入节拍下的事件定义**

时间口径先行固定：示教离线评估的 `t_switch` 指预测对应的原始观测时刻（`t_pred_obs`）；未实际测得的响应/命令时间保持空值，不能把它宣称为端到端切换延迟。真实运行另以 `t_text_first/t_text_confirm` 记录文本响应，以 `t_command` 记录新条件首次实际采用，分别相对同一时钟下的 ready/window 评分。下文离线“首次/后续”指实际送入模型的观测及其预测，实机则同时记录对应响应。

- 稠密评估以真实帧时间戳验证 0.3 秒保持。低频评估初版要求第一次正确预测与至少一次后续观测的正确预测，且观测时间跨度达到 0.3 秒；无后续观测的尾部事件记为确认不足/右删失。正常后继阶段短于确认窗口时另记短阶段事件并按预先固定规则评分，不能强迫模型停留而把正常继续推进算成回退。
- 分别保存首次正确且事后稳定的 `t_text_first` 与 `t_text_confirm`，同时统计首次短暂正确后又回退的事件。后续观测只用于离线确认，不反馈给更早时刻的模型，也不要求运行时为了这个指标多等一帧。约 0.764 秒一次的输入不能直接验证“只提前 3–5 帧”的在线控制精度。
- 固定每个 episode 的请求时间清单，R0/R1/R2 使用同一清单做模型能力比较。按时间选取不晚于请求时刻的最近帧，不使用可能在未来的最近邻；对不同采样起始相位做少量固定复测，避免边界恰好落在请求点带来的偶然收益。R2 每条轨迹从空历史运行。真实服务的端到端延迟另测，不能把固定输入清单当成闭环运行时序。
- 新指标按“到达正确后继并稳定”评分，同时记录切换前的预测阶段；不强制前一预测必须恰好为 old。跳级、错误中间阶段和额外回退另记，预测事件不得重复匹配；保留现有 direct old→new 最近边界指标作附表。短阶段被低频采样整个漏过、从错误阶段进入 new、始终未到达 new 必须区分，全部保留在总事件清单中。
- 明确区分相对 `t_label` 的误差、相对 readiness 的等待，以及超过 `t_latest` 的超时。窗口后延迟用 `max(0, t_switch - t_latest)`；明确越界提前依据 ready 不确定区间下界判定，处于不确定区间的结果单报，不能算作已验证窗口内交接。保守窗口内率仅统计达到 ready 上界且未超过 `t_latest` 的事件。
- 选模同时看固定时限内稳定交接率、漏切换/超时率及条件延迟分位数；分位数必须注明是否仅对已切换事件计算、零延迟是否计入。未切换和确认不足不会凭空获得有限延迟；第 8 节的 P95 降幅不能脱离失败率单独决定通过。分别按 task/transition 报告，避免一个任务的改善掩盖另一任务恶化。

当前 `transition_metrics` 强制输入完整稠密 episode，内部又使用数组位置计算帧误差。因此低频评估应由新 evaluator 处理原始时间戳，不能简单稀疏抽样后把序号冒充原始帧号传入旧函数。

**13.3 R1 的实现范围与损失一致性**

首轮固定为 S-only、边界/稳定样本各约 50%、纯 CE、`lambda_pair=0`，不同时加入 R2 或改 chunk 长度。旧 M3 的配置记录 `lr_subtask=1e-4`，所以 `1e-5` 确为其配置峰值的 0.1 倍；它是新优化器的起始候选，不是继承旧训练终点的瞬时 LR。

逐样本有效 token 平均已存在；新增权重时明确目标为 `sum(weight_i * CE_i) / sum(valid_weight_i)`，零有效权重须有一致处理。八卡/梯度累积后应等价于一个全局 batch 的该目标；不能让各 rank 在有效样本数量或权重不同的情况下各自除以局部分母，再把结果当成全局加权平均。通过有不同文本长度、mask 和权重的小样本检查验证这一点。

采样日志记录边界/稳定组比例、各 task/transition/episode 暴露次数及重复帧比例。首先仅改变采样分布，不对所有边界再统一施加大 loss 权重；权重主要表达审核可靠性与明确的 ready 监督。冻结 B/A 的参数与 buffer、S 非零梯度、全局有效样本统计、首步输入输出和 checkpoint 正常加载均应留下证据。正式候选用独立 variant/loader，并维持旧加载入口行为。

**13.4 时钟、动作采用与 R2 状态协议**

代码复核发现客户端收到结果后先记录 query、更新视频文本，随后才进行关节跳变检查和逐步下发。因此显示新文本不等于已经执行新动作。现有 `action_step_times` 也会在 readonly 模式写入；必须结合 `executing`、实际发送步数和终止状态解释，不能把 readonly 节拍算成物理命令。

诊断保留 `snapshot_monotonic`、各传感器 ROS 时间与 age、`response_monotonic`，新增记录实际 command 的本机 monotonic 时间；旧日志的 wall-clock 动作时间可用同一 query 的 wall/monotonic 锚点近似换算，并注明误差。不能直接相减不同机器的 monotonic 值，也不能把客户端快照时间当成三相机曝光完全同步。离线窗口兼容性需要同时检查 native 原始动作和现有控制变换后的命令，尤其是夹爪裁剪及关节跳变拒绝。

R2 在共享模型权重之外为各连接维护独立、有限长度的状态；`run_id` 改变、重连、任务变化、复位和历史超龄时清空。协议需包含请求/响应序号及 chunk 标识，区分“候选生成”“服务已选用条件”“客户端实际采用”。客户端回传上一 chunk 的 ID/执行步数用于状态对账，不回传人工指定的 subtask 文本。遇到响应超时、重复/乱序请求、动作被拒绝或只执行部分 chunk，按预先约定的重置/重新识别规则处理，不能默认上一阶段已经执行完成；连接关闭需释放缓存。

上述状态协议只属于 R2；R1 可沿用无状态服务。新增 T/D 的训练路径及分布式梯度检查与第 6 节的 detach/no_grad 修正同时完成，不能只检查 decoder 有梯度就宣布整个 S 分支通过。
