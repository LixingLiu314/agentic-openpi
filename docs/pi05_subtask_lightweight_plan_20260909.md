# Subtask 相似场景混淆：轻量模型方案修订

2026-09-09。状态：方案与数据审计完成，尚未实现、训练或改动 Agilex 推理行为。本文替代上一版方案中的新增终止标签、双层历史和任务阶段图建议；已核实的实机错误证据仍保留。

## 1. 按用户修正重新界定问题

用户说明“最后 release 盖子”是口误，因此撤回把“缺少独立 release/done 标签”作为主要原因或必须先处理事项的判断。原数据以 Put the lid on the box 结束是事实，但不能单凭标签粒度认定它有问题，也不能据此要求重标注。

仍成立的证据：三个候选存在提前跳阶段、后段回到早期阶段、长时间停留或目标物体混淆；三者的 S 都没有跨推理请求的状态。这里的 context.memory 是当前观测特征，文字内部的自回归也不是任务时间上的记忆。当前 14 维机械臂状态已经编码进输入，不能把问题说成“完全没用 state”。

相似图像未必严格不可区分，S 的当前观测能力也可能不足；尚不能证明所有错误都来自缺乏记忆。但若当前观测确实不足以区分两个任务时刻，完全无状态的结构无法仅靠调整分类头稳定补出缺失的过去信息。建议用一个小型跨步状态检验这一假设，不承诺它会解决全部动作问题。

## 3. 主方案：只给 S 增加一个固定大小的可学习跨步状态

保留 B → S 生成 subtask → A 根据该文本预测动作的结构。S 增加一组小型递归 memory tokens，首个候选建议 4 × 512 维；不保留过去图片，不另建事件表，不把 token 对应到人工阶段。

每次推理：

1. B 按原流程处理当前三路图像、机械臂 state 和全局任务，得到当前特征 X_t。
2. 小型门控注意力模块结合 X_t 与上一轮状态 M_(t-1)，更新 M_t。旧状态提供过去信息，门控决定保留和改写什么。
3. 原 S 文本解码器同时读取完整的当前特征与 M_t，生成原格式的 subtask 文本。当前观测有直接输入路径，避免只能依赖压缩后的记忆。
4. 原 A 使用这次实际生成的同一段文本预测动作；M_t 留给下次请求。

可概括为：M_t = Update_S(M_(t-1), stopgrad(B(o_t, task)))；subtask_t = Decode_S(current_features, M_t)；action_t = A(original_conditioning, subtask_t)。新 episode 从可学习初始状态开始。

这仍然使用历史，但只通过一个固定大小的隐状态传递，省去上一版的短期图像窗口、长期事件存储、执行事件整理和额外完成/恢复输出头。4 × 512 的单份持久状态在 FP32 下约 8 KiB；这是状态缓冲大小，不是整个模块的显存、参数或训练成本。token 数是待验证起点。

对盖子场景，预期 S 能从此前观测保留“已经历搬运/放回”的信息；对 food，它应允许完成一轮后开始下一轮；对 three_object，它应结合已见过程与当前剩余物体选择子任务。这里只描述应学习的能力，不把这些语义写成状态机字段或人为规则。

选择观测驱动的隐状态，而非直接把上一条预测文本作为唯一历史，可减少一次错误文字被显式循环反馈的问题。隐状态仍可能记错或过度依赖先前过程，必须评估，不能声称消除了错误累积。

这种跨段传递少量 memory tokens 的基本思路可参考 [Recurrent Memory Transformer, NeurIPS 2022](https://arxiv.org/abs/2207.06881)。该论文提供结构依据，不是本项目 VLA 效果的实验证据；这里的观测更新、门控和 S/A 接口属于本项目待验证设计。

## 4. 数据基本不动，但采样必须支持时间顺序

保留现有视频、task/subtask 字符串、state、action、归一化规则与文件格式。只利用已有 episode_index、frame_index、timestamp 做顺序采样，不新增人工标注或历史特征文件。不将部分数据附带的 traj_cot、cam_high_subgoal 等字段擅自加入输入。

建议每次展开 4 个观测时刻，相邻约 0.5–1 秒，并在训练中抖动间隔以覆盖当前约 0.7 秒的请求节奏；实际帧步长由各数据集 timestamp 决定，不能一律假定帧率。各训练流沿本 episode 继续运行，跨训练块保留状态但截断梯度，episode 结束时清空。只在随机短片段开头清零，会削弱长任务进展的学习，不作为主要训练方式。

现有每 rank 32 个观测的预算可以尝试组织为 8 条流 × 4 个时刻，8 rank 合计仍是 256 个观测/optimizer update。每个时刻保留原 subtask CE 与 action 监督；损失归一化以有效观测数计算，不暗中增加 action 更新次数。B 可批量计算当前帧特征，S 沿时间顺序更新。具体 packing 必须通过真实容量和吞吐检查，不能把状态小等同于训练零开销。

实现时有两个关键边界：

- 更新状态的输入只有当前观测特征和先前隐状态；不能拿含真实 subtask 答案的 teacher-forcing 隐层来更新它。训练中一句文本内部的正常 teacher forcing 可以保留，真实上一阶段标签不能成为部署时不存在的输入。
- B 特征继续 detach，但新 S 记忆必须保留 CE 梯度。现有 decoder 内部会 detach memory，不能简单把新增 token 拼入后又一并切断其梯度。CE 只训练 S 及其新模块，action loss 仍只训练 A 与允许开放的 B。

推理状态按独立客户端会话隔离，新任务/新运行/切换 checkpoint 时重置；不能放在共享模型对象里让不同客户端串用。一次观测只更新一次，重试不能重复推进。保留现有输入字段，不要求客户端上传历史图像。这部分是少量必要的服务生命周期改动。

原茄子数据继续固定 train158/val20/test20，不读取封存 test。五类新数据的 metadata 目前都标记为 train 范围，后续训练前需要正常的 episode 级划分清单和 train-only normalization；这不要求重写原数据，但不能直接把全部数据当训练集再在其中报告泛化分数。

## 5. 最小实验与判断标准

第一轮先比较两种结构，B 冻结以隔离 S 的作用：现有无状态 S，以及带上述小型状态的 S。两个候选使用完全相同的顺序采样与帧预算，避免把采样改动误当作结构收益；现有三组只能作为额外历史参照。

两项都从官方 pi05 B/A 权重开始，共有 S 层采用相同 seed42 初始化，新增模块另行确定性初始化，优化器与计数清零；不从现有三组或 M3/R1/R2 继承。保持原 5000 updates、global256、LR 与保存验证节奏，先做容量检查。这是后续实验建议，本次没有启动作业，也没有新增恢复旧队列的授权。

先在当前茄子数据判断是否确实缓解已知混淆；通过后，用同一结构扩展五类数据，优先 food（合法循环）与 three_object（多种顺序），再覆盖 EAI、擦拭与香蕉避障。无需同时重新排列三种 B 开放组合。各新数据集上的基线与候选必须使用一致的训练、划分和评估协议。

验证采用完整 validation episode 的因果回放，模型自己维护状态，不喂真实历史标签；覆盖标签边界与长距离相似场景，报告每类 subtask 的精确匹配/F1、跳错阶段、错误对象、切换延迟和漏切换。用原始参考序列判断错误，不能把编号下降或 release→reach 一概算错；重复标签的每次出现需按参考时间段区分。

对同一已训练候选，在同一当前观测下比较正常记忆与每次清零记忆，检查收益是否真正来自历史，并测试中途接入/重置后的表现。跨 episode 的划分、时间间隔扰动与不同任务顺序共同检查它是否只学会计时推进。离线回放使用录制轨迹，不能代替闭环成功率。

最终同时检查 A 的原生动作误差及经用户安排的闭环任务表现。已有证据显示部分正确 Put 文本下 A 仍可能给出闭爪目标，所以 S 改善不等于释放/整任务已解决。不要用更稳定但一直卡住的文本作为成功，也不要仅按 128 帧平均 flow MSE 选择新候选；序列语义、动作验证和具体选模规则应在新训练前固定。

## 6. 本轮范围

建议仅引入“一个 S 侧递归隐状态 + 顺序采样 + 会话重置”。暂不引入新 release/done 标签、双层历史、人工阶段图、固定候选分类头、额外完成/恢复任务或更大 B。先用配对实验检验这个最小结构变化，再决定是否需要进一步设计。
